# Prompt 07.5: Comparacion de PostgreSQL y Redis

## Contexto

El proyecto tiene sus microservicios dentro de `library_soap_gsm/proyecto_bien`. PostgreSQL contiene el esquema `library` y el microservicio SOAP consulta el catalogo. Redis se instala y ejecuta en Ubuntu sobre WSL2. La prueba se lanza desde CMD de Windows: PostgreSQL se consulta desde Windows y Redis se alcanza mediante `localhost:6379`.

## Solicitud

Prepara una prueba reproducible que compare el tiempo de una lectura puntual del mismo libro en PostgreSQL y en Redis. PostgreSQL debe ejecutar una consulta parametrizada por ISBN contra `library.books`; Redis debe devolver con `GET` el mismo JSON de ese registro previamente almacenado como valor. Usa conexiones persistentes y una clave temporal unica que se elimine al finalizar.

El benchmark debe:

- Leer la conexion PostgreSQL desde el `.env` existente sin mostrar usuario, contrasena ni URL en la salida.
- Leer `REDIS_URL` desde el entorno, con valor local predeterminado `redis://localhost:6379/0`.
- Comprobar conectividad, existencia de un libro y equivalencia exacta del contenido entre PostgreSQL y Redis antes de medir.
- Permitir configurar iteraciones y calentamiento; alternar el orden de las lecturas para reducir sesgo.
- Medir cada operacion con `time.perf_counter_ns()` y presentar milisegundos: minimo, media, mediana, p95, maximo y operaciones por segundo secuenciales estimadas.
- Informar versiones de Python, PostgreSQL y Redis, tamano de la respuesta y razon entre medianas.
- No escribir datos permanentes en PostgreSQL, no borrar la cache ajena y limpiar la clave temporal creada por la prueba.

## Procedimiento requerido

1. Iniciar Redis en WSL2 desde CMD y confirmar `PONG`.
2. Activar el entorno virtual en `proyecto_bien` e instalar el cliente Python `redis`.
3. Ejecutar el benchmark desde CMD de Windows contra PostgreSQL local y Redis de WSL2, usando al menos 1,000 iteraciones y 50 de calentamiento.
4. Registrar los resultados reales del equipo, el entorno y las limitaciones. No inventar tiempos ni afirmar que Redis siempre sera mas rapido.
5. Entregar el script ejecutable, instrucciones de ejecucion, tabla comparativa, interpretacion de resultados y conclusion en `ejercicioRedis.md`.

## Criterios de aceptacion

- Se puede repetir sin modificar la base ni detener los microservicios.
- Si falta Redis, PostgreSQL o el libro, se muestra un error entendible y no se reportan resultados falsos.
- La comparacion aclara que mide lecturas secuenciales locales con conexiones persistentes, no rendimiento concurrente ni latencia de produccion.
- Se explica que PostgreSQL sigue siendo la fuente persistente y Redis es una capa en memoria/cache, no un reemplazo equivalente de la base relacional.
